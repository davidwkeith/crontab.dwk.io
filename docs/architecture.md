# Architecture

## Stack decisions

**Astro 7** — Static site generator. Zero client JS by default, fast builds. Bundled scripts are always emitted as external files (`vite.build.assetsInlineLimit: 0` in `astro.config.ts`) because the CSP forbids inline scripts.

**Cloudflare Workers** — `run_worker_first: true`, static assets via `env.ASSETS.fetch()`, `not_found_handling = "404-page"`. Output directory: `dist/`. See `docs/cloudflare.md`.

**TypeScript strict** — Build-time errors instead of runtime failures.

## Styling

CSS custom properties in `src/styles/global.css`. Terminal aesthetic with dark/light mode via `prefers-color-scheme`. Monospace system font stack throughout.

Design documented in `docs/brand.md`.

## Pages

Single-page site:

- `/` — Crontab clock (interactive terminal UI)
- `/404.html` — Terminal-styled error page, served with a 404 status for any missing path (`noindex`)

Each page has one visually hidden `<h1>` (`.sr-only`); the terminal title bar is decorative. The clock uses `role="timer"` (not `aria-live`) so screen readers aren't interrupted every second.

No blog, no CMS, no content collections.

## Images

`public/og-image.png` (1200x630 social card) and `public/apple-touch-icon.png` (180x180) are generated by `npm run site-images` (`scripts/generate-site-images.ts`, uses `sharp`). The outputs are committed; re-run after a design change. `BaseLayout` emits `og:image`/`twitter:image` on every page, defaulting to the card.

## Checks

`npm run typecheck` runs `astro check` (covers `.astro` files). `tsconfig.json` extends `astro/tsconfigs/strict` and excludes the Anglesite setup scripts that need `execa`/`consola`.

## Output

`static` mode in Astro config. All pages pre-rendered at build time. Deployed as Cloudflare Worker serving static assets.

## Migration

Converted from Eleventy 3 + WebC to Astro 5 on 2026-03-20. The terminal clock design, CSS, and JavaScript were preserved from the original site.
